# 0.5.1 验收

## 选区识别白页修复

在 0.5.0 独立程序中，使用本机已有配置复现：画布保留 8 条手写笔迹，点击“选区识别”后预览像素全部为空。相同操作在新配置中能显示笔迹。

原因是记住了自由截图工具，但全屏批注没有实际的自由选区顶点，导出却仍按空多边形裁剪。0.5.1 仅在存在至少三个顶点时应用多边形裁剪，保留全屏截图和真实自由截图选区。

回归通过实际鼠标笔画书写分式，依次点击公式画笔、“选区识别”，拖动框选并调用真实识别服务。分别覆盖普通画笔、公式画笔及自由截图选区；核对预览有笔迹、空白选区被拒绝、发送图仅含笔迹与白底、识别结果和剪贴板一致。测试未注入期望识别结果，未将排版图片作为手写输入。

最终独立包的三种选区识别链路全部通过，分式均正常输出；其中 1/3 精确匹配，另外两例将大写 `X` 识别为小写 `x`。另有公式画笔转换 3/3 精确匹配、剪贴板公式样例 5/8 精确匹配，其余同为大小写差异。保留识别原文，未将期望答案写回结果。

## 存档保留

默认保留最近 7 天；设置可改为 1–3650 天，0 表示永久保留。启动后、每小时及设置变更后检查，批注、识别和安装更新时延后。过期整份存档通过 Electron 的系统回收站接口移动，失败时保留原件。

8 项新增单元测试覆盖严格的到期边界、近期和未来记录、关闭与自定义天数、不明文件与损坏记录、链接目录、工作状态变化、回收失败、每小时检查及清理期间修改设置。类型检查、Lint 和合计 85 项单元测试通过。

实际 Electron 设置页验证了默认值、保存后重启、非法数值拒绝，以及 320、375、414、768、1440 像素宽度。未替换 `shell.trashItem` 的集成测试将 8 天前的测试存档移入 Windows 回收站，保留近期和含不明文件的目录；关闭清理并重启后保留 30 天前的记录，改为 1 天后按新期限执行。另从 Windows 回收站回读确认测试目录及原位置。

## 独立包

冻结的 Windows x64 ZIP 通过 30 个验收阶段，包括无需开发运行时启动、设置、D 键圈选与清除、连续书写、三档显示缩放、公式画笔、Math Academy 兼容输出和真实 OCR。包内 73 个程序文件有 SHA-256 清单；发行审计未发现运行配置、截图或凭据。

首次运行中有渲染进程异常和外部剪贴板变化；失败项在同一冻结 ZIP 上重跑并通过。验收脚本补充了新增设置字段，并在选区提示改变布局后重新读取位置。公式转换的“不写入剪贴板”检查改为计数应用自身的写入调用，避免将用户在其他程序复制的内容误判为软件写入。

## 自动更新验收边界

本次本机验收使用已安装的 0.5.0 和公开的 0.5.1 GitHub Release。仅将“上次检查时间”设为超过 24 小时以触发到期检查；下载、校验、空闲安装和重启均由应用已有更新器执行，不替换更新源、不手动执行安装脚本。最终本机回执另行核对版本、运行进程、全部程序文件、登录设置与历史归档。

公式转写仍需核对大小写与上下标。功能通过与精确匹配分别记录，不将两者混为一项结果。
